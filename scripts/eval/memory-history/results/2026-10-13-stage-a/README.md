# 2026-10-13 留存评测（第二批）：检索修复第一步

对应产品改动：历史检索的**词法路线按窗口计分**（`windowTurns`，默认 2 轮一个窗口）、**向量路线保持文档级**、`rankHistory` 的 **`recency` 选项**（新近度加权，默认力度 0.1、半衰期 30 天，只在有向量路线且没有显式时间意图时生效）。**不改存储，不改返回内容**：命中后返回的仍是完整文档。

上一批（`../2026-10-13/`）量的是"窗口级向量"这个理想配置；生产里每个会话只存一个文档级向量，所以这一批用**真实的 `rankHistory` 新选项**重新量了一遍能不改存储就得到的收益。方法、数据、纪律（dev 选参数、holdout 只跑冻结配置）与上一批相同，见上一批的 README。

## 结果（Hit@1，括号内是 95% 自助法区间）

### dev，规模 250

| 方式 | 改动前（整段） | 改动后（窗口 2 轮） |
|---|---|---|
| 纯词法 | 39% [28–51] | **51% [38–62]** |
| 混合（文档级向量） | 41% [29–54] | 43% [32–55] |
| 混合 + 新近度 0.1 | – | 48% [36–60]，更正顺序 **80%** |
| 混合 + 重排 8 条（生产现状的本地路径） | 36% [25–48] | 38% [26–49] |

规模 512 与 250 一致（纯词法 52%，混合 42%，混合 + 新近度 46%）。

### 独立留出集，规模 250

| 方式 | 改动前（整段） | 改动后（窗口 2 轮） |
|---|---|---|
| 纯词法 | 45% [23–68] | **55% [32–77]** |
| 混合 | 55% [32–77] | 59% [36–82] |
| 混合 + 新近度 0.1 | – | 62% [38–81]，更正顺序 **67%**（混合 33%） |
| 混合 + 重排 8 条 | 41% [23–64] | 50% [27–73] |

### 窗口大小与力度（dev，规模 250）

| 窗口 | 纯词法 | 混合 | 混合 + 新近度 |
|---|---|---|---|
| 1 轮 | 46% | 46% | 48% |
| **2 轮** | **51%** | 43% | 48% |
| 4 轮 | 49% | 45% | 49% |

新近度力度（混合，窗口 2）：0.05 → 48%、更正顺序 60%；0.1 → 48%、80%；0.2 → 43%、80%。

## 读法与结论

1. **窗口化词法是这一步里确定的收益**：dev +12、holdout +10 个点，两个集合方向一致，规模 250 与 512 一致。窗口 2 轮比 1 轮、4 轮略好，但差异在噪声内，**没有证据说 2 就是最优**，只能说不差。
2. **在不改存储的前提下，纯词法加窗口（dev 51%）比混合（43%）和混合加新近度（48%）的 Hit@1 都高。** 文档级向量是对整段会话算的，对长会话很糊，融合时拖累了窗口化后的词法精度。上一批里窗口级向量 + 去停用词 + 新近度是 dev 64%、holdout 71%，所以**收益大头来自窗口级向量，需要改存储（会话 → 窗口的向量）**，这一步还没做。
3. **新近度确实改善更正顺序**（混合下 dev 40% → 80%，holdout 33% → 67%），整体 Hit@1 小幅提高；**但它只在向量路线上生效**。默认关闭向量时，更正顺序仍是 40%。
4. **负结果**：想在纯词法路线上用"相邻两项相关度差不超过 δ 且后者更新时交换"来补，更正顺序只从 40% 到 40%–50%，Hit@1 还略降（51% → 46%–49%）。新旧两版在词法分数上本来就不是并列的，真正起作用的是向量带来的语义相近。不建议再试这个方向。
5. 生产现状的"混合 + 重排 8 条"在两个集合上都不是最好的，且每次约 0.85 秒。

## 局限

与上一批相同：合成数据；dev 69 条、holdout 22 条有答案的查询，区间宽，**区间重叠时不能说谁更好**；更正类 dev 10 条、holdout 3 条；用户原话直接当查询；延迟来自一台 24 线程机器。额外一条：超长会话在生产里会被摘录预算（6000 字）整段丢弃，这一步**没有解决它**（需要另行设计摘录证据，见 PR 说明）。
