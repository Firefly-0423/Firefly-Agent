# 2026-10-13 留存评测：窗口切分与更正顺序

本目录是一次**完整的、可复现的**对照实测，目的是回答两个问题：

1. 把"整段会话做一个检索单元"改成"两轮一个窗口"，是否真的改善找回？
2. 相关度接近时让新事实优先（新近度加权），能否改善"更正后用新事实"？

## 测试配置（每份 JSON 的 `meta` 里都有）

- 数据：合成语料，种子 `20261013`，规模 250 与 512 个会话（窗口粒度分别是 1733 与 2230 个检索单元）；`datasetDigest` 与 `querySetDigests` 记录在 JSON 中，数据或查询一变就对不上。

- 新近度：`score × (1 + α·exp(−ln2·天数/半衰期))`，只作用在前 30 个候选上；默认 α=0.1、半衰期 30 天。
- 环境：纯 Node 24、Windows、顺序执行、无并发；延迟是这台机器上的数字，不是目标设备的结论。

## 结果摘要（Hit@1，括号内是 95% 自助法区间）

### dev，规模 250

| 方式 | 整段会话 | 两轮窗口 |
|---|---|---|
| 纯词法 | 39% [28–51] | 51% [38–62] |
| 混合（向量 + 词法） | 41% [29–54] | 52% [41–64] |
| 混合 + 去停用词 | 42% [30–54] | 55% [43–67] |
| 混合 + 重排 8 条（**生产现状的本地路径**） | 36% [25–48] | 55% [43–67] |
| 混合 + 新近度 0.1 | 43% [31–55] | 60% [46–72] |
| 混合 + 去停用词 + 新近度 0.1 | **51% [39–63]** | **64% [52–75]** |

规模 512 的数字与 250 基本一致（见各 `.md`）。

### 独立留出集，规模 250

| 方式 | 整段会话 | 两轮窗口 |
|---|---|---|
| 纯词法 | 45% [23–68] | 55% [32–77] |
| 混合 | 55% [32–77] | 59% [41–82] |
| 混合 + 重排 8 条 | 41% [23–64] | 64% [45–82] |
| 混合 + 去停用词 + 新近度 0.1 | 67% [48–86] | **71% [52–90]** |

### 更正顺序（新事实排在旧事实前面的比例）

| | 无新近度 | 新近度 α=0.03 | 0.05 | 0.1 | 0.2 | 0.3 |
|---|---|---|---|---|---|---|
| dev，混合（窗口） | 40% | 50% | 60% | **80%** | 80% | 80% |
| dev，混合 + 去停用词（窗口） | 20% | 30% | 70% | **80%** | 80% | 80% |
| holdout，混合（窗口） | 33% | – | – | 67% | – | – |

整体 Hit@1（混合 + 去停用词 + 新近度，dev 窗口）随力度：0.03 → 58%，0.05 → 63%，**0.1 → 64%**，0.2 → 58%，0.3 → 52%。**0.1 在平台期，更大反而整体变差。** 半衰期 14/30/90 天为 61%/64%/63%，差异在噪声内。

## 读法与结论

1. **窗口切分是最大的杠杆之一**：纯词法 +10 到 +12 个点（dev 39% → 51%，holdout 45% → 55%）。"长会话里的一句话"这一类：dev（12 条）从 0%–8% 升到 67%–100%，holdout（4 条）从 0%–50% 升到 75%–100%。方向在两个集合上一致，但 holdout 只有 4 条。
2. **新近度明显改善更正顺序**（40% → 80%），并且在混合检索下提高整体命中；**单独加在纯词法上会变差**（dev 51% → 43%，holdout 55% → 33%）。不要在没有向量的路径上启用它。
3. **混合相对纯词法的优势小且区间重叠**（+1 到 +4 个点）；去停用词的效果时有时无（对更正顺序还有负作用）。在默认关闭向量的前提下，这两项不应成为主要卖点。
4. **生产现状的路径（整段 + 混合 + 重排 8 条）没有比纯词法更好**（dev 36% 对 39%，holdout 41% 对 45%），且重排整段会话要约 0.9 秒。
5. 剩下的更正失败（dev 2 条：`q-theme`、`q-g-c02`）原因是旧句子恰好含有查询词（"偏好"、"主题"），新句子换了说法，新近度补不平相关度的差距。

## 局限（务必一起读）

- **合成数据**，措辞比真实对话规整；这是决策和回归工具，不是质量证明。
- **查询很少**：dev 69 条有答案，holdout 22 条；更正类 dev 10 条、holdout 3 条，所以更正顺序的百分比颗粒很粗（一条就是 10 或 33 个点）。**区间重叠时不能说谁更好。**
- **用户原话直接当查询**，是最坏情况；真实流程里是模型自己改写查询再调用检索，改写类（paraphrase）会好一些。这一点没有被量到。
- **新近度只对"现在是什么"类问题安全**，对"我当初说过什么"会起反作用，数据集里没有后一类问题。
- 窗口粒度的向量是每个窗口单独算的；**生产里每个会话只存一个文档级向量**，窗口级向量需要改存储，这里量到的"窗口 + 混合"收益不能直接等同于不改存储就能得到的收益（这是后续检索修复要单独处理的存储改动）。
- 评测的是排序层，不含授权、来源校验、摘录预算等治理逻辑；摘录预算（6000 字）会让生产里超长会话根本返回不了，这一点也没有被量到。
- 延迟和内存来自一台 24 线程机器，纯 Node，不代表目标设备。
