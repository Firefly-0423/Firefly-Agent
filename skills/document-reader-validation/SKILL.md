# 文档读者校验

这是 Firefly 独立编写的文档工作流，主责为知更鸟。先确认读者与目的，再检查结构和事实，用读者问题验证理解，最后修订。现有文档、需求及证据是输入；技能本身不授权发送、发布、改写无关文件或创建子任务。

## 1. 读者与目的

记录读者的背景、已有知识、使用场景，以及读完后要理解的结论或完成的具体操作。已有明确需求时沿用，不重复追问。缺少决定文档走向的信息时，列出最关键缺口，交由主流萤向用户确认；在不依赖该答案的部分继续整理。

用一句话写下成功标准，例如：首次使用者能够找到独立测试应用、填写自己的专用凭据，并知道保存后应停在哪一步。作者熟悉内容不能代替目标读者理解。

## 2. 结构与事实检查

按读者实际要做的顺序组织内容，将先决条件放在操作前，将结果及失败后的下一步紧邻对应操作。保留既定模板、语言、格式及需求范围。

将关键说法对应到可核对的来源：提供的文件、源码、报告、实际测试或用户说明。区分已验证事实、合理推断和未验证项；路径、名称、版本、费用、权限和可执行步骤从实际材料提取。缺少证据时标明缺口，不补造。未签名目录包不等于安装验证，部分网络控制不等于所有外连控制，未知费用不等于免费。

## 3. 读者问题

写出能检验成功标准的三至五个具体问题，而非只问“看懂了吗”。例如：从哪里开始？完成后能看到什么？这项结论由什么支持？出现错误应停在哪一步？谁需要确认下一步？

先仅依据文档尝试回答，记录找不到答案、答案矛盾、依赖作者口头解释的地方。自查只能标为模拟检查。

需要独立读者验证时，向主流萤提交读者背景、文档版本、问题和预期成功标准，由主流萤协调读者测试。专业 agent 不调用 delegate_agent、不再次委派，也不私自联系实际读者。读者只收到完成任务所需的资料；避免暴露凭据或无关私人内容。未安排或未完成的检查明确写“未执行”。

## 4. 修订与交付

优先修正阻止读者完成目的的事实或步骤，再处理结构和表达。沿用用户确定的范围；新增需求或范围变化交还主流萤，不凭读者意见自行改变规格。

交付包含：读者与目的、修订后的内容或明确修改位置、关键事实来源、读者问题及实际答案、仍未解决的缺口和读者测试状态。标明检查的文档版本；修改后仅复核受影响的问题。没有真实读者反馈时，交付仍可使用，但不得宣称已经通过读者测试。
