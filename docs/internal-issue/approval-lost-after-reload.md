# 渲染页重载后，仍在等待的审批没有可处理的卡片

状态：修复已提 PR（#93，待合并）
日期：2026-11-16

## 现象

在 `per-action` 档位下，工具调用等待审批时聊天页重载。如果原运行没有因重载被取消（见下文“影响范围”），主进程仍在等这次审批，每 10 秒重播一次审批卡。重载后的页面不认识这次运行；按 G1（施工包 G，PR #92），带了运行 ID 却找不到所属会话的卡不再投到当前可见会话，所以聊天窗口里没有这张卡。提醒窗口只显示普通的“流萤在等你的批准”，点开只到聊天窗口，用户没有地方批准或拒绝。

## 触发条件

1. 档位为 `per-action`，运行发起一次需要审批的工具调用（`src/main/platform/permission/permission.ts` 的 `requestApproval`）。
2. 审批还在等时，聊天页主框架导航（刷新）。
3. 原运行没有被取消（只在桌面记忆不管理的会话里成立，见下文）。

## 影响范围

- 默认启动下，刷新会撤销页面的桌面记忆授权，原运行随之被取消，审批以 cancelled 结算、提醒撤下，不会出现本问题；但这本身是另一个缺陷，见 [切换会话或刷新会取消正在进行的运行](./run-cancelled-on-switch-or-reload.md)。
- 本问题出现在桌面记忆不管理的会话里（例如 `--firefly-memory-controlled` 启动时的 Work、Code，以及模型档案不匹配的 Chat）；那个缺陷修复后，所有会话都会遇到，因此必须先有处理入口。

## 根因

1. 审批的生命周期由主进程持有（无超时，直到作答或运行取消），聊天页的运行登记只在渲染进程内存里，重载后不会重建。
2. G1 有意不把无法归属的卡投到当前会话，避免误投（`src/renderer/react/features/chat/pages/interaction-owner.ts`）。
3. 原有的审批提醒只负责提醒，没有按审批 id 向主进程核实并就地作答的入口。

## 当前状态

PR #93 修复：所有审批提醒都带“查看审批”入口。主进程按审批 id 找原请求，现场核实：

- 原运行仍在所属会话里：显示所属会话、发起伙伴、工具和关键参数，可以批准或拒绝；
- 找不到原运行：不给批准；
- 已结算、已取消、已接管：显示“审批已失效”；
- 没有运行 ID：只显示，不能批准。

作答前主进程再核实一次，审批只结算一次；打开详情、点提醒、点关闭都不撤卡，结算后才撤。

不在范围内：重载后聊天列表里那条回复仍可能显示“已中断”。运行结果已完整写进主进程的会话记录，但聊天消息由页面写。负责人要求先做“刷新后的状态判断与终态回填”，再做“页面接回运行”。
