# 运行中插入的提交与恢复施工计划

日期：2026-11-16
状态：已完成施工包 1–7 及自动验证，真机待验收
Issue：#96（负责人已批准持久化改动）
设计依据：负责人确认的方案；Codex 只读评审四次（方案、本 PR 范围、施工包 5 两轮），评审记录在本地，未入库
进度：`queue-insert-commit-progress.md`

**目标：** Work、Code 运行中“立即发送”的排队消息，插入下一次模型请求时不丢、不重复、不被半截重放。
**范围：** 本 PR 只做提交与恢复契约；模型说明（中文固定模板）、过程流气泡、页面接回运行是后续 PR。

## 负责人已定

- 先写聊天历史，再写会话记录（transcript）；默认记忆路径与 `pending-adjustment.ts` 文件头的“失败即关闭”约束一起改。
- 失败时：已成功的前缀照常交给运行并写进检查点；下一次模型请求前有限重试；仍补不上就停止运行、保留可恢复记录。不让模型带着未生效的补充继续执行。
- 本 PR 包含：运行检查点里的交付凭据、新运行开始前的跨运行对账。
- 模型说明固定中文；已插入的补充被编辑时“先检查，没问题就补全之前的，然后接着做”（后续 PR）。
- 仍只在 Work、Code；带附件的消息仍不能插入。

## 持久化改动（#96）

1. 聊天历史用户消息新增可选 `runInsertion: { version: 1, runId, assistantTurnId?, revision, sequence }`，只由主进程在 `commitPendingAdjust` 写；渲染端不能伪造，`upsert` 回写不能擦掉；旧消息没有该字段即普通历史。
2. 运行检查点新增交付凭据（`messageId`、`revision`、来源 `runId`、接纳轮次、顺序），与 `messages` 同次保存；显式空集合表示“没有”，旧检查点缺字段表示“未知”，不解释为“都没交付”。
3. 会话记录（transcript）格式不变；正文仍是用户原文。

## 状态模型

| 聊天历史 | 会话记录 | 检查点凭据 | 含义 | 下一步 |
|---|---|---|---|---|
| 未提交（仍在队列，带运行标记） | 无 | 无 | 待插入 | 提交聊天历史 |
| 已提交（带 `runInsertion`） | 无 | 无 | 已接收，会话记录待补 | 补写会话记录（同 id 已存在时读出核对正文） |
| 已提交 | 已存在 | 无 | 待交付 | 交给运行并写检查点 |
| 已提交 | 已存在 | 已保存 | 已进入运行上下文 | 不再交付 |

## 施工包（单 PR，按提交拆分，每步各自通过测试）

- [x] **1. 聊天历史字段**：`chat-types.ts` 增加 `runInsertion` 类型；`commitPendingAdjust` 同次写入（含 `assistantTurnId`、`revision`、`sequence`）；提供“读取某运行已提交、按顺序的插入”的查询；`chats-ipc.ts` 剥离渲染端传入的 `runInsertion`、`upsert` 保留已有值。测试：提交写入字段、旧数据兼容、IPC 伪造被剥离、回写不擦除、索引失败不导致重复提交。
- [x] **2. 检查点交付凭据**：`run-store.ts` 的会话与检查点类型增加凭据集合（校验、旧格式 = 未知）；`agent-loop.ts` 的 `checkpoint` 随 `messages` 一起保存；`agent-loop-adapter.ts`、`run-recovery.ts` 传递与恢复。测试：保存与读回、旧格式、快照成功而 journal 失败后的读回。
- [x] **3. 拉取结果契约**：`RunAdjustmentMessage` 带 `revision`；拉取结果改为 `{ delivered: 消息[], blocked?: { messageId, reason, retryable } }`；`agent-loop.ts` 两个边界：先接纳并检查点保存成功前缀，再对 `blocked` 做有限重试（下一请求前），仍失败以“插话提交失败”结束；最终边界未排空不报成功。测试：A 成功 B 失败、重试后成功、重试耗尽、最终边界、取消与超时留下可对账状态。
- [x] **4. 普通路径反转与恢复**：`pending-adjustment.ts` 先提交聊天历史、再写会话记录；同 id 已存在时读出核对正文（不一致即冲突，不交付）；按 `runInsertion` 找回“已提交未交付”的条目，先于新标记的队列条目交付；并发与单一接收者约束保持；文件头约束改写。测试：历史失败不写会话记录不出队、会话记录失败后重建拉取器可恢复、同 id 不同正文冲突、并发拉取、重复实例、跨运行跨会话、撤回与编辑竞争。
- [x] **5. 默认记忆路径反转**：`main-default-memory.ts` 的处理器与 `conversation-transcript-adapter.ts` 的 `commitRunAdjustment`：先校验运行授权与边界、提交聊天历史与来源凭据，再在原边界后写会话记录；历史已提交后的重试走“已提交恢复”分支，不再次准备来源；严格校验不放松。测试：同上在默认记忆下的完整链路。
- [x] **6. 跨运行对账**：新运行派发前（`agui-bridge` 与会话记录协调器），把上一运行“历史已提交、会话记录缺失”的插入补写进会话记录（按原顺序、核对正文）；不依赖恢复 failed 运行。测试：上一运行失败留下的 history-only 条目在新运行前被补齐，上下文不重复。
- [x] **7. 文档**：本计划与进度、相关 AGENTS.md 链接、`docs/internal-issue/` 记录。
