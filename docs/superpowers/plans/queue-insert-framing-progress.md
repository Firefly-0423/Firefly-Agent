## 实机测试（2026-11-17）

环境：开发版（`npm start`），独立开发档案，Work 模式，模型 DeepSeek（负责人在开发档案里配置）。场景和界面问题与 [#97 的验证报告](queue-insert-commit-progress.md) 一致，本文只记加框相关的结果。

- **运行中交付：** 运行检查点里交给模型的那条用户消息是：
  ```
  【运行中补充】用户在你执行任务的过程中补充了以下内容：
  补充：总结里请先写一句“已收到补充”，再写正文。
  请先检查已经完成的部分是否需要按这条补充调整，没有问题就补全之前的工作，然后接着做。
  ```
  聊天历史和会话记录里是原文。模型的总结按补充开头写了“已收到补充”。
- **从会话记录重建：** 关闭应用、模拟会话记录丢失其中一条插入，重启后发新消息。新运行交给模型的上下文里，三条插入各出现一次、都带说明，包括刚补齐的那条；作为普通排队消息发出的那条不带说明。会话记录里插入条目带 `runId`，普通用户消息不带。
- **没有重复加框：** 每条插入的说明头只出现一次。
