## 行为契约

1. 完整审核失败后，详情重新读取 Main 的当前状态，显示已知阻断，不保留一个可反复提交的旧预览。失败后的详情读取、版本切换、返回、刷新、卸载均受同一代际检查保护；响应身份须匹配来源、路径与固定提交。
2. 外部市场文案说明纯文本导入、默认禁用与单独启用确认；可见性描述覆盖当前实际支持的 Work 和 Code，不继承当前安装列表的 Code 文案。已知依赖阻断优先于“尚未完成审核”的一般提示。
3. Main 分别提供最新发现、当前政策下已审核固定版本与已安装版本的只读身份。安装身份来自经过现有证明校验的 committed 状态；发现/审核不等于已安装。刷新不改变已安装内容，也不使新提交继承旧审批。
4. Renderer 只选择 Main 已知的 `latest` 或 `reviewed`，携带期望提交作一致性断言；不能提交任意仓库、路径、内容或审批。Main 从静态审核表选择当前政策下唯一的最新审核记录，固定提交读取完整目录；即使最新目录删除该技能，已有审核入口仍可达。无可用审核记录、重复冲突或政策不符时关闭入口。
5. 审批匹配来源、完整提交、路径、完整内容摘要、政策版本；完整目录、文件模式、文本结构、许可证、体积、路径、hash 校验继续执行。政策版本不匹配不批准。现有审核记录只绑定其原字节，不新增任何候选审批。
6. OpenAI 以根 `plugin.json` 和固定 `skills/` 为优先入口，支持已有 `.codex-plugin/plugin.json` 回退；Claude 支持 `.claude-plugin/plugin.json`、标准 `skills/` 与声明的局部技能目录。继续兼容 `anthropics/skills` 当前显式 `skills[]` 目录。所有读取仍局限两个固定仓库和固定提交。
7. 格式解析只读。非空 MCP、hooks、commands、agents、LSP、工作流、依赖、安装配置等宿主组件，或技能本身的脚本、二进制、非本地引用、宿主专用前置要求，均给出组件/路径级原因并阻断原候选。空的组件配置不代表执行授权。未实现自动衍生包；不能静默删文件或要求。原 `remotion-markup` 保持阻断。
8. 导入暂存、一次性 token、有效期、可信主 frame、默认禁用、单独启用、Code/Work 注册和回滚边界保持；只读展示信息不能进入严格安装清单。

## 官方格式依据

- [OpenAI Package your plugin](https://developers.openai.com/plugins/build/plugins)：根 portable manifest、固定组件路径、兼容 overlay 优先级。
- [Submit a Claude plugin to OpenAI](https://developers.openai.com/plugins/guides/submit-claude-plugin)：源宿主审批不转移，技能与 MCP 的适配范围不同。
- [Claude plugin manifest reference](https://code.claude.com/docs/en/plugins-reference)：`.claude-plugin/plugin.json`、默认/额外技能目录和其他组件。本宿主实现上述格式的保守纯文本部分，不声称实现 Claude/OpenAI 完整运行时。
