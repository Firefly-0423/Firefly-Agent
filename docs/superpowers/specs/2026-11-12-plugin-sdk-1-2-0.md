# Firefly 插件 SDK 1.2.0 规格

状态：设计规格（待负责人审阅）
日期：2026-11-12
分支：`dev/firefly-1.2.0`

输入：负责人 2026-11-10 的四项决定（直白命名；外部渠道默认 Chat；线上目录禁止原生模块；模型用量默认限频并可见）、2026-11-12 的数据目录决定（`%APPDATA%\Firefly-1.2.0`）、一份独立的 SDK 设计提案（只取思路，命名与权限按 Firefly 实际重写）。

## 1. 目标与范围

1.2.0 的插件 SDK 是一套全新设计：

- 不兼容 0.x 的插件、清单和接口，不提供迁移层。
- 插件运行在独立进程里，崩溃不影响 Firefly。
- 插件只拿到清单声明且用户允许的宿主能力，每项能力都能撤销。
- 插件工具走 Firefly 现有的权限档位和审批，插件不能绕过。
- 命名直白，开发者不需要先学一套隐喻。

不在本规格内：线上插件目录的审核流程（另写）；插件市场界面改版（随 1.2.0 界面主题）。

## 3. 能力命名

插件入口拿到一个 `ctx`，能力全部挂在上面：

| `ctx.` | 作用 | 对应需求 |
|---|---|---|
| `tools` | 给流萤注册工具（Work / Code 模式可用） | 加工具 |
| `context` | 每轮发给模型前提供一段上下文 | 给提示词加上下文 |
| `channels` | 接入外部聊天渠道（收发消息、报告连接状态） | 接入聊天渠道 |
| `model` | 借用用户配置的模型：生成文字，或发起一次完整运行 | 使用宿主模型 |
| `events` | 订阅运行开始/结束、工具完成、定时任务完成 | 感知运行 |
| `sessions` | 分页读取会话和消息（只读） | 读会话 |
| `workspace` | 读当前会话绑定的项目目录 | 读工作区信息 |
| `schedules` | 提议、修改、删除定时任务（用户确认后生效） | 定时任务 |
| `secrets` | 加密保存插件自己的凭据 | 保存密钥 |
| `ui` | 设置页面板、独立窗口 | 自己的界面 |

## 4. 清单 `firefly.plugin.json`

```json
{
  "schemaVersion": 1,
  "id": "dev.firefly.weather",
  "name": "天气查询",
  "version": "1.0.0",
  "sdk": "^1.2.0",
  "description": "查询城市天气。",
  "author": { "name": "示例作者" },
  "license": "MIT",
  "main": "dist/index.mjs",
  "icon": "assets/icon.png",
  "platforms": ["win32"],
  "native": false,
  "tools": [
    { "name": "get_weather", "title": "查询天气", "risk": ["network"], "modes": ["work", "code"] }
  ],
  "context": [
    { "id": "now_playing", "title": "正在播放", "modes": ["chat", "work"], "sources": ["user", "schedule"] }
  ],
  "channels": [],
  "permissions": ["model.generate", "secrets"],
  "ui": {
    "settings": { "entry": "ui/settings.html", "title": "天气设置" },
    "windows": [{ "id": "radar", "entry": "ui/radar.html", "title": "雷达图", "width": 480, "height": 360 }]
  }
}
```

校验规则（宿主导入时和 `firefly-plugin validate` 都执行，任一失败即拒绝安装）：

1. `schemaVersion` 必须为 `1`；出现 0.x 清单字段（如旧的 API 版本字段、钩子字段）直接拒绝，并提示“这是 0.x 插件，1.2.0 不再支持”。
2. `id`：反向域名，`^[a-z0-9]+(\.[a-z0-9-]+){2,}$`，6–64 字符。`version` 为 SemVer。`sdk` 必须满足当前宿主版本。
3. `main`、`icon`、`ui.*.entry` 是包内相对路径：规范化后不得逃出包根目录（不允许 `..`、绝对路径、盘符、指向包外的符号链接）；`main` 必须是存在的 `.mjs` 或 `.cjs`。
4. 静态闭合：运行时注册的工具名、上下文 id、渠道 id、窗口 id 必须与清单一致，否则注册调用返回 `ERR_UNDECLARED`。
5. `tools[].risk` 取自 Firefly 实际的风险类型（`src/shared/permission-approval.ts` 的 `ToolRiskLevel`）中的 `fs-read`、`fs-write`、`shell`、`network`、`input-control`，至少一项。插件工具**不允许**声明 `safe`（§7.3）。
6. `tools[].modes` 只能是 `work`、`code` 的子集；Chat 模式不挂插件工具。
7. `native: true` 的包不能进入线上目录；本地安装可以，启用时显示高风险提示（§9）。
8. `permissions` 取值：`model.generate`、`model.run`、`events`、`sessions.read`、`workspace.read`、`schedules`、`secrets`、`ui.windows`。注册 `tools` / `context` / `channels` 由对应数组声明，不另列权限。

## 5. 运行模型

### 5.1 进程

- 每个已启用插件一个 Electron `utilityProcess`。宿主为它准备干净的环境变量（不继承 Firefly 进程里的任何密钥、代理凭据和用户环境变量），工作目录设为插件数据目录。
- 插件代码一旦启用即在自己的进程里拥有 Node 能力。**进程隔离保护的是 Firefly 宿主的稳定和宿主数据，不是沙箱**：插件进程本身可以访问网络和文件系统。因此“启用一个插件”意味着信任它的代码，这一点要在启用确认框里写明。宿主能力（模型、会话、密钥、工作区、审批）只能通过 SDK 申请，宿主数据不对插件进程开放。
- 插件界面在独立的 `WebContentsView` / `BrowserWindow` 中运行：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`，只加载包内静态资源，强制 CSP（禁外部脚本）。界面只能通过 `window.fireflyPlugin` 桥与本插件的进程通信。

### 5.2 通信

- 传输：`MessagePortMain`，载荷必须可结构化克隆（纯数据、`Uint8Array`；不传函数）。
- 帧：`req`（带 `id` 和截止时间）、`res`、`cancel`（对端触发对应 `AbortSignal`）、`chunk` / `end`（流式生成、事件订阅）。
- 每个请求都有截止时间；宿主到期未收到 `res` 即按超时处理。

### 5.3 超时与崩溃

| 情况 | 宿主行为 |
|---|---|
| `context` 提供者超过 1500 ms 或抛错 | 跳过这一段上下文，记一条日志，本轮照常发送 |
| 工具执行中用户点停止 | 立即发 `cancel`；3 秒内未结束，工具结果记为 `cancelled`，宿主收回控制 |
| 插件进程崩溃 | 正在执行的工具结果记为 `unknown`（崩溃前可能已有外部副作用，不能当成“没执行”）；按 1 s → 5 s → 30 s 退避重启 |
| 60 秒内崩溃 3 次 | 插件置为“已停用（异常）”，关闭它的窗口，通知用户 |
| 内存超过上限（默认 512 MB） | 宿主定期读取该进程的内存（`app.getAppMetrics()` 按 pid 匹配），超限即结束进程，按崩溃处理 |

`utilityProcess` 本身不提供内存或 CPU 硬上限；1.2.0 用上表的轮询方式。是否另做 Job Object 原生辅助程序见 §13 决定 3。

## 6. 能力 API

下面是接口草图，实现时以这里的语义为准，类型细节在 `plugin-sdk/src` 定稿。

### 6.1 入口与公共类型

```ts
export type Mode = "chat" | "work" | "code";
export type RunSource = "user" | "schedule" | "plugin" | "channel";
export type ToolRisk = "fs-read" | "fs-write" | "shell" | "network" | "input-control";

export type PluginErrorCode =
  | "ERR_UNDECLARED"        // 清单没有声明
  | "ERR_PERMISSION"        // 用户未授予或已撤销
  | "ERR_REJECTED"          // 用户在审批中拒绝
  | "ERR_CANCELLED"
  | "ERR_TIMEOUT"
  | "ERR_INVALID_ARGUMENT"
  | "ERR_RATE_LIMITED"      // 超出模型用量上限
  | "ERR_UNAVAILABLE"       // 宿主服务暂不可用（如未配置模型、没有工作区）
  | "ERR_INTERNAL";

export class PluginError extends Error {
  readonly code: PluginErrorCode;
  readonly retryable: boolean;
}

export interface Disposable { dispose(): void }

export function definePlugin(plugin: {
  activate(ctx: PluginContext): void | Promise<void>;
  deactivate?(reason: "disabled" | "quit" | "upgrade" | "fault"): void | Promise<void>;
}): typeof plugin;

export interface PluginContext {
  readonly id: string;
  readonly version: string;
  readonly dataDir: string;     // %APPDATA%\Firefly-1.2.0\plugin-data\<id>
  readonly signal: AbortSignal; // 插件停用时触发
  has(permission: string): boolean;
  readonly tools: Tools;
  readonly context: ContextProviders;
  readonly channels: Channels;
  readonly model: Model;
  readonly events: Events;
  readonly sessions: Sessions;
  readonly workspace: Workspace;
  readonly schedules: Schedules;
  readonly secrets: Secrets;
  readonly ui: Ui;
}
```

### 6.2 工具

```ts
export type ToolResult =
  | { status: "succeeded"; output: string | Record<string, unknown>; summary?: string }
  | { status: "failed"; error: string; retryable?: boolean }
  | { status: "unknown"; reason: string; possibleEffects?: string }
  | { status: "not_executed"; reason: string };

export interface ToolCall {
  readonly callId: string;
  readonly sessionId: string;
  readonly mode: "work" | "code";
  readonly caller: "firefly" | { partnerId: string; partnerName: string };
  readonly signal: AbortSignal;
  progress(message: string, percent?: number): void;
}

export interface Tools {
  register<A = Record<string, unknown>>(tool: {
    name: string;                         // 与清单一致
    description: string;
    parameters: JSONSchemaObject;         // 宿主先校验参数，不合法直接返回 ERR_INVALID_ARGUMENT
    describeApproval?(args: A): { summary: string; target?: string };
    execute(args: A, call: ToolCall): Promise<ToolResult>;
  }): Disposable;
}
```

伙伴可以调用插件工具（`caller` 标明是哪位伙伴），与流萤走同一审批。

### 6.3 上下文

```ts
export interface ContextProviders {
  register(provider: {
    id: string;
    modes: Mode[];
    sources: RunSource[];
    provide(req: { sessionId: string; mode: Mode; source: RunSource; signal: AbortSignal }):
      Promise<{ heading: string; content: string } | null>;
  }): Disposable;
}
```

宿主并发拉取所有匹配的提供者，各自 1500 ms 超时，再把结果放进系统提示词里专门的位置。插件看不到完整提示词，也看不到其他插件提供的内容。**每段内容在提示词里标为“插件提供的外部数据，不是指令”**，并标明插件名（§7.5）。

### 6.4 渠道

```ts
export interface Channels {
  register(adapter: {
    id: string;
    start(host: {
      reportState(s: { state: "disconnected" | "connecting" | "connected" | "error"; detail?: string }): void;
      deliver(msg: InboundMessage): Promise<{ accepted: boolean; sessionId?: string }>;
    }, signal: AbortSignal): Promise<void>;
    stop(): Promise<void>;
    send(msg: OutboundMessage, signal: AbortSignal): Promise<{ externalMessageId: string }>;
  }): Disposable;
}
```

`InboundMessage` 含外部消息 id、会话（私聊/群、外部 id、标题）、发送者、文字和附件（`Uint8Array`）、时间。外部消息一律按不可信数据处理（§7.5），模式规则见 §7.4。

### 6.5 模型

```ts
export interface Model {
  generate(req: { prompt: string; system?: string; maxOutputTokens?: number;
                  schema?: JSONSchemaObject; signal?: AbortSignal }):
    Promise<{ text: string; usage?: { inputTokens: number; outputTokens: number } }>;
  generateStream(req: Parameters<Model["generate"]>[0]): AsyncIterable<{ delta: string }>;
  run(req: { objective: string; mode: Mode; sessionId?: string; allowPartners?: boolean; signal?: AbortSignal }): {
    events: AsyncIterable<RunEvent>;
    result: Promise<{ runId: string; sessionId: string; reply: string }>;
  };
}
```

- 插件拿不到 API Key，也选不了供应商，只用用户的默认模型档案。
- `run` 发起的运行和用户自己的运行一样受权限档位和审批约束；运行出现在会话列表里，来源标为该插件。
- 用量：每个插件默认每分钟最多 10 次 `generate` / `run`，超出返回 `ERR_RATE_LIMITED`。插件正在借用模型时，界面显示“〔插件名〕正在借用流萤思考”，可一键停止。上限在插件设置里可调。

### 6.6 事件、会话、工作区

```ts
export type HostEvent =
  | { type: "run.started"; runId: string; sessionId: string; mode: Mode; source: RunSource; at: number }
  | { type: "run.ended"; runId: string; sessionId: string; outcome: "completed" | "cancelled" | "failed"; at: number }
  | { type: "tool.completed"; runId: string; tool: string; status: ToolResult["status"]; durationMs: number; at: number }
  | { type: "schedule.completed"; taskId: string; outcome: "completed" | "cancelled" | "failed"; at: number };

export interface Events { on<T extends HostEvent["type"]>(type: T, fn: (e: Extract<HostEvent, { type: T }>) => void): Disposable }

export interface Sessions {
  list(o?: { cursor?: string; limit?: number; mode?: Mode }): Promise<Page<SessionSummary>>;
  messages(sessionId: string, o?: { cursor?: string; limit?: number }): Promise<Page<MessageRecord>>;
}

export interface Workspace {
  current(sessionId?: string): Promise<{ sessionId: string; mode: Mode; root: string | null; name: string | null } | null>;
  onChange(fn: (b: Awaited<ReturnType<Workspace["current"]>>) => void): Disposable;
}
```

事件只读、不阻塞运行。`workspace` 只给路径和名称；插件读写项目文件仍要通过自己的工具并经过审批。

### 6.7 定时任务

```ts
export type Schedule =
  | { kind: "cron"; expression: string; timezone?: string }
  | { kind: "once"; at: number }
  | { kind: "interval"; minutes: number };

export interface Schedules {
  propose(spec: { title: string; schedule: Schedule;
                  action: { type: "run"; prompt: string; mode: Mode } | { type: "callback"; payload?: unknown } }):
    Promise<{ taskId: string; status: "pending_approval" }>;
  update(taskId: string, patch: Partial<Parameters<Schedules["propose"]>[0]>): Promise<{ status: "pending_approval" }>;
  remove(taskId: string): Promise<boolean>;
  list(): Promise<TaskRecord[]>;
  onTrigger(fn: (e: { taskId: string; payload?: unknown; signal: AbortSignal }) => Promise<void>): Disposable;
}
```

`propose` 立即返回 `pending_approval`，不阻塞当前回复；用户在任务面板确认后才生效，改期同样要确认。到点无人值守时，若运行需要 `fs-write`、`shell`、`input-control`，挂起并发桌面通知等用户批准。

### 6.8 密钥与界面

```ts
export interface Secrets {
  set(key: string, value: string): Promise<void>;
  get(key: string): Promise<string | null>;
  delete(key: string): Promise<boolean>;
  keys(): Promise<string[]>;
}

export interface Ui {
  openWindow(id: string, state?: unknown): Promise<{ close(): Promise<void>; post(msg: unknown): Promise<void> }>;
  onMessage(fn: (e: { from: { kind: "window" | "settings"; id: string }; method: string; params: unknown }) => Promise<unknown>): Disposable;
  post(to: { kind: "window" | "settings"; id: string }, msg: unknown): Promise<void>;
}
```

密钥由宿主用 Electron `safeStorage`（Windows 上是 DPAPI）加密，按插件 id 隔离，与 Firefly 自己的模型密钥分开存放。

## 7. 权限与审批

### 7.1 三层

1. **清单边界**：未声明的能力和工具直接 `ERR_UNDECLARED`。
2. **用户授予**：安装后默认停用。启用时列出清单里的工具、上下文、渠道和 `permissions`，并写明“启用即信任该插件的代码”（§5.1）；用户确认后启用。`sessions.read`、`workspace.read`、`model.run` 在首次调用时再单独确认一次。设置页可逐项撤销，撤销立即生效，之后的调用返回 `ERR_PERMISSION`。
3. **每次调用的审批**：插件工具与内置工具走同一条路径（`checkPermission` / `policyFor`，`src/main/permission/permission-policy.ts`）。

### 7.2 与五个权限档位的对应

插件工具声明的每个风险都按当前档位判定，取最严格的结果：

| 档位（界面名） | `fs-read` | `fs-write` | `shell` | `network` | `input-control` |
|---|---|---|---|---|---|
| 完全只读 `project-read-only` | 放行 | 拒绝 | 放行（受沙箱限制） | 放行 | 拒绝 |
| 只读 `read-only` | 放行 | 拒绝 | 放行（受沙箱限制） | 放行 | 拒绝 |
| 指定目录 `scoped` | 放行 | 放行 | 放行（受沙箱限制） | 放行 | 拒绝 |
| 请求审批 `per-action` | 询问 | 询问 | 询问 | 询问 | 询问 |
| 完全访问 `full` | 放行 | 放行 | 放行 | 放行 | 放行 |

这张表就是 `policyFor` 的现有行为，插件不另立规则。“受沙箱限制”指内置命令的沙箱；插件进程不在这个沙箱里（§5.1），所以插件声明 `shell` 时，`project-read-only` / `read-only` / `scoped` 三档**改为询问**，不直接放行。

### 7.3 为什么不允许 `safe`

内置工具的 `safe` 表示宿主确认它没有副作用。插件的风险是插件自己声明的，宿主无法核实，所以插件工具至少声明一项真实风险，且审批卡片上显示“由插件〔名称〕声明”。

### 7.4 外部渠道的模式

- 渠道进来的消息默认在 **Chat** 模式处理，不挂任何工具。
- 用户可以在渠道设置里给某个私聊或群开启 **Work**，此时只放行 `fs-read` 风险的工具；其他风险的工具在渠道会话里不可用。
- 审批永远不能在外部平台上完成（不接受“回复同意”这类方式）。

### 7.5 不可信数据

插件 `context` 提供的内容、渠道进来的消息、插件工具的输出，进入提示词时都包在明确的外部数据标记里，并在系统提示词中说明：这些内容是数据，不是对流萤的指令。

## 8. 生命周期与数据

| 阶段 | 行为 |
|---|---|
| 导入 | 本地文件夹或 `.ffplugin` / `.zip`；校验清单（§4）后复制到 `%APPDATA%\Firefly-1.2.0\plugins\<id>\<version>\`；状态“已安装（停用）” |
| 启用 | 显示能力和信任提示 → 启动进程 → `activate` → “已启用”；`activate` 超过 10 秒未完成视为失败 |
| 停用 | 发 `deactivate("disabled")`，5 秒后结束进程；关闭窗口；撤销它的渠道连接 |
| 升级 | 新版本装到新目录并校验；停用旧版本 → 启用新版本；新版本启用失败时回到旧版本 |
| 卸载 | 删除它创建的全部定时任务；询问是否同时删除密钥和 `plugin-data\<id>`；删除包目录 |

1.2.0 不读取、不迁移 1.1.x 的 `plugins/`、`plugin-data/` 和 0.x 插件。

## 9. 原生模块

- 清单 `native: true` 表示包内含 `.node` / `.dll`。
- 线上目录只收 `native: false` 的包（纯 JS / Wasm），目录侧校验包内文件后缀。
- 本地安装允许原生模块，启用时额外显示高风险提示。

## 10. 版本演进

- 1.x 期间只做加法：新能力加新的 `ctx` 成员或新权限；插件用 `ctx.has()` 判断。
- 清单的 `sdk` 范围决定宿主能否加载；宿主拒绝加载时给出“需要 Firefly ≥ x.y”。
- 破坏性变化只在 2.0 出现，并提前一个小版本在文档和启用提示里预告。

## 13. 实施步骤

每一步都能单独合入并通过测试。

1. **SDK 包骨架**：重写 `plugin-sdk/`（类型、错误、`definePlugin`、清单 JSON Schema、`validate` 函数、`firefly-plugin` CLI）。测试：清单校验的表驱动用例（每条规则的通过与拒绝两侧，断言具体错误码和字段路径）；包边界用临时目录里的真实文件测越界路径和符号链接。
2. **宿主进程与通信**：`utilityProcess` 启动、干净环境变量、`MessagePortMain` 帧、超时与取消、崩溃退避与熔断、内存轮询。测试：环境变量里不含宿主密钥；`cancel` 后对端 `signal.aborted`；崩溃时执行中的工具结果为 `unknown`；60 秒 3 次崩溃后状态为“已停用（异常）”且不再重启（用假定时器）。
3. **工具与审批**：注册、参数校验、四态结果、与 `policyFor` 对接、`shell` 在受限档位改为询问、伙伴调用。测试：五档 × 五种风险的表驱动判定；被拒绝时插件 `execute` 没有被调用。
4. **上下文与不可信标记**：并发拉取、1500 ms 超时、提示词槽位与标记。测试：超时的提供者被跳过且本轮照常发送；插件内容出现在标记内，且不出现在其他插件可见的数据里。
5. **模型、事件、会话、工作区**：限频、借用提示、`run` 的来源标记与审批。测试：第 11 次调用返回 `ERR_RATE_LIMITED`；撤销 `sessions.read` 后返回 `ERR_PERMISSION`。
6. **定时任务**：`propose` / 确认 / 改期 / 无人值守挂起 / 卸载清理。
7. **密钥与界面**：`safeStorage` 加密、按插件隔离；窗口 CSP、桥接只能到本插件。
8. **渠道**：适配器、Chat 默认、按会话开 Work（只放行 `fs-read`）、外部平台不接受审批。
9. **生命周期与插件管理界面**：导入、启用确认（含信任提示和原生模块提示）、升级回滚、卸载。
10. **示例插件与 `firefly-plugins` 迁移**：两个示例；7 个现有插件按 1.2.0 重写，更新 `registry.json`。
11. **发布**：SDK 1.2.0 与应用 1.2.0 同时发布；之后执行 §12 的弃用命令。
