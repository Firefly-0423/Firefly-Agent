**条目要点（提炼自计划`先写的测试`与`实现`）：**

- **A1**
  - 前置状态：控制器就绪，分别处于 Chat、Work、Code 三种模式（以三模式表驱动）。
  - 操作或事件输入：依次收到 reasoning、正文事件和成功终态。
  - 可观察结果：正文与过程顺序正确；流式结束后无 loading；最终检查点包含正确 run、用户锚点和终态；只报告一次持久化完成。
  - 禁止副作用：无额外派发、意外写入或跨会话更新。
- **A2**
  - 前置状态：Work 或 Code 会话运行中。
  - 操作或事件输入：经工具过程后收到正式回答。
  - 可观察结果：工具状态、结果、变更和正式回答分别可观察。
  - 禁止副作用：工具过程不能被误当正式回答重复保存；无额外派发、意外写入或跨会话更新。
- **A3**
  - 前置状态：会话运行中且已产出部分输出，另存在另一会话。
  - 操作或事件输入：触发取消，之后收到迟到正文事件。
  - 可观察结果：部分过程保留；终态为 cancelled。
  - 禁止副作用：正式回答不提交；迟到正文不能重新写回；另一会话不受影响；无额外派发、意外写入或跨会话更新。
- **A4**
  - 前置状态：消息已发送，尚未收到 run ack。
  - 操作或事件输入：在 ack 前取消，随后收到 ack 返回。
  - 可观察结果：ack 返回后仅取消其分配的 run。
  - 禁止副作用：不执行 cancel-all；没有孤儿 run 或残留 busy；无额外派发、意外写入或跨会话更新。
- **A5**
  - 前置状态：会话运行中，可注入网络/请求/运行时故障。
  - 操作或事件输入：分别触发网络中断、请求超时、`runtime_error`。
  - 可观察结果：精确错误代码与中文公开提示正确（复用公开错误映射）；终态及过程落盘。
  - 禁止副作用：原始私密错误不进入展示或文件；无额外派发、意外写入或跨会话更新。
- **A6**
  - 前置状态：运行中存在可控延迟的旧检查点写入（running 状态）。
  - 操作或事件输入：旧检查点写入延迟期间终态到达并触发终态写入，随后以实际文件重载确认。
  - 可观察结果：最后重载结果为终态。
  - 禁止副作用：不能被 running 检查点覆盖；不能提前报告持久化完成；无额外派发、意外写入或跨会话更新。
- **A7**
