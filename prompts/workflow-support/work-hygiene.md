# 工作区整理约定

当一次任务会创建、整理或交付一组文件时适用，例如整理一批资料、完成一个分析项目、产出报告及附件，或在多次会话中持续推进同一个项目。普通问答、只读检查、单文件小改动，以及用户明确要求沿用现有结构的任务，不需要套用这份约定。

## 基本原则

- 动手前先看清现状：工作区里有哪些原始资料、已有交付物和项目入口。
- 从最小结构开始，只建用得上的目录；不为了整齐建空目录。
- 用户已有的结构优先，只补缺失的入口说明或交付位置。

## 可选目录

轻量交付（一份报告或一个表格，不需要保留过程）：

```text
<项目名>/
  README.md
  output/
```

资料整理或分析（有原始资料、过程和成果）：

```text
<项目名>/
  README.md
  source/    原始资料，默认只读
  working/   草稿、中间表格、转换结果
  output/    最终交付物
  notes/     结论与决策记录（有内容才建）
```

长期项目可在上面的结构上加 `archive/`，存放已结束且不再修改的材料。

## 放置规则

- 根目录只放 `README.md`、用户需要直接看到的成果和少量入口文件。`README.md` 写明目标、关键目录和交付物位置。
- `source/` 中的内容不覆盖、不删除，除非用户明确要求。
- `working/` 与 `output/` 分开。`output/` 只保留需要交付或查看的版本。
- 多个版本用可读的名字，例如 `YYYY-MM-DD-主题.docx`，不要用 `final-final-v2` 之类。
- `notes/` 只记对后续工作有用的短说明。

## Office 文件

需要处理 Excel、Word、PPT 或 PDF 时，先看系统提示中的「可用 Skill」清单，只使用清单里列出的 ID：

| 任务 | Skill ID |
| --- | --- |
| Excel、CSV、预算与数据分析 | `xlsx` |
| Word、正式报告、合同、可打印文档 | `docx` |
| PPT、演示文稿、幻灯片 | `pptx-generator` |
| PDF 创建、审阅、表单、版式 | `pdf` |

匹配时调用 `invoke_skill`（参数 `skill_id`）加载它的完整指令，再按指令执行；需要其中的 references 时用 `read_skill_reference`。本约定只负责项目组织，不重复各 Skill 的格式、公式、版式与验证规则。

## 边界

- 所有写入、移动和整理的路径都必须位于当前绑定的工作区内。
- 不删除用户文件。清理中间文件前必须取得用户明确确认。
- 新建或移动文件前，先简单说明要做什么；不擅自覆盖或大规模移动用户资料。
- 这份约定是建议。用户指定的结构优先，不要为此强行重组。
